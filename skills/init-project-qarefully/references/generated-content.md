# Generated Content

Read before instruction-file write, review, repair, Verify. Apply bundled style to generated instruction files only; no copy of style resource outside package.

- Default omit. Source pointer + reason to inspect; complex logic needs entry point, authority, non-obvious risk. Detailed docs -> path, never copied explanation.
- Avoid volatile implementation prose (line numbers, function bodies, transient values), inventories, exhaustive environment lists, generic coding advice, host-provided routing rules.
- Root = global context; Full nested files = subtree-only deltas. Preserve source/conditions/scope/labels when compressing; projected records supply placeable factual meaning, writer renders wording once.
- Canonical behavior -> one owning home. Verified warnings with different edit triggers may point to the same source authority with distinct IDs/homes; write only each trigger's hazard, never repeat invariants or a flow narrative. Light -> root only. Compact app/package route/test navigation must reflect checked source mapping, not a per-test inventory.
- Source citations must exist and contain the claimed authority. Missing generated/install output -> cite existing producer/configuration; name the output as generated in ordinary prose when needed, never as an existing authority. Path checks stay strict.
- Destructive command -> impact + required authorization. Generated/runtime boundary -> identify only when agent may accidentally edit/commit it.
- Omit initializer plumbing, run folder, skill locations/discovery. Instruction-file pointers per policy Shape. Pitfalls verified + nonempty per repository policy.

Root only -> include following rules; never nested:

```md
# Maintenance
Update this file or closest nested instruction file when guidance becomes stale; durable boundaries, hazards, sources of truth change; or reusable lessons, workarounds, user instructions emerge. AGENTS.md/CLAUDE.md conflict with repository evidence -> warn user with "WARNING".

# AI Documentation and Code Comments
AI docs and code comments -> terse facts for future agents; non-obvious architecture, decisions, cross-cutting constraints only. Default no comment; edit only when needed. Omit history, dates, code narration. One fact -> one home across docs/comments; warnings with different edit triggers are distinct facts.
```

Generated files use behavioral labels or `intent unknown` -> append legend for used items only to AI Documentation paragraph:

- `Invariant:` -> intended behavior, preserve.
- `Limitation:` -> known gap, quirk, or bug, not contract; fix only when task asks.
- `intent unknown` -> ask before changing.
